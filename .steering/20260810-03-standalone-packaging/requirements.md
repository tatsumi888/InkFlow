# 要求内容

## 概要

InkFlow を、Python やライブラリが入っていない Windows 環境でもそのまま動く**単独実行可能な形**にパッケージングする処理を追加する。PyInstaller で GUI 用と CLI 用の実行ファイルを生成し、配布用のZIPまでを1コマンドで作れるようにする。

## 背景

現状の起動手順は `.venv\Scripts\python.exe -m inkflow`、あるいは `run.bat`（`.venv` を前提）で、**リポジトリと仮想環境が揃っていないと動かない**。

InkFlow は月1回しか起動しない道具であり、そのたびに Python 環境の状態を気にするのは運用として重い。また、別のPCへ持ち出したい・環境を作り直したときにすぐ使いたい、という場面で毎回 `pip install` からやり直すのは現実的でない。実行ファイル1つ（もしくは1フォルダ）で完結していれば、コピーするだけで使える。

## 実装対象の機能

### 1. 実行ファイルの生成

- PyInstaller で Windows 用の実行ファイルを生成する。
- **GUI 用**（コンソールを出さない）と **CLI 用**（コンソールに出力する）の2つを作る。GUI をコンソール付きで起動すると黒い窓が残り、CLI をコンソールなしで起動すると出力が一切見えないため、1つの実行ファイルでは両立できない。
- 生成物にはアイコンとバージョン情報を埋め込む。

### 2. 配布形式

- **onedir**（1フォルダ・既定）と **onefile**（1ファイル）の両方を選べる。
  - onedir は起動が速く、2つの実行ファイルがライブラリを共有できる。
  - onefile はコピーが簡単だが、起動のたびに一時ディレクトリへ展開するため遅い。
- onedir の場合、配布用にZIPへまとめる。

### 3. ビルドコマンド

- 1コマンドでビルドできるようにする。PyInstaller が未導入なら導入を促す（または導入する）。
- ビルド後に生成物のサイズと、実行ファイルが実際に動くかの確認結果を表示する。

### 4. アプリアイコン

- アイコン画像をコードから生成する（バイナリ資産をリポジトリに置かない）。
- 生成したアイコンは実行ファイルに埋め込むだけでなく、**GUI のウィンドウアイコンにも使う**。パッケージ版でもソース実行でも見た目が揃う。

## 受け入れ条件

### 実行ファイルの生成

- [ ] ビルドコマンドを実行すると、GUI 用と CLI 用の実行ファイルが生成される。
- [ ] 生成された CLI 実行ファイルで `layouts` / `devices` を実行すると、一覧が正しく表示される。
- [ ] 生成された CLI 実行ファイルで、PDFフォルダから EPUB を生成できる（Python 環境に依存せず動く）。
- [ ] 生成された EPUB の内容が、ソースから実行した場合と一致する。
- [ ] GUI 実行ファイルにコンソールウィンドウが付かない。

### 配布形式

- [ ] 既定（onedir）でビルドすると、1つのフォルダに両方の実行ファイルとライブラリが入る。
- [ ] onedir のビルド結果が配布用ZIPにまとめられる。
- [ ] `--onefile` を指定すると、単独で動く実行ファイルが生成される。

### ビルドコマンド

- [ ] PyInstaller が未導入の環境で、何をすればよいかが分かるメッセージが出る。
- [ ] ビルド後に生成物のパスとサイズが表示される。
- [ ] ビルド後の動作確認（CLI 実行ファイルの起動）が自動で行われ、失敗すれば非ゼロで終了する。

### アプリアイコン

- [ ] アイコンがコードから生成され、複数サイズを含む `.ico` が書き出される。
- [ ] 生成した `.ico` が実行ファイルに埋め込まれる。
- [ ] GUI のウィンドウアイコンに同じ図柄が使われる。

### 既存機能への影響

- [ ] 既存のテストがすべて通る。
- [ ] ソースからの実行（`python -m inkflow` / `run.bat`）が従来どおり動く。

## 成功指標

- Python が入っていない Windows PC に生成物をコピーするだけで、GUI・CLI とも動く。
- onedir 版の起動が実用的な速さ（数秒以内）である。onefile 版との起動時間の差を実測して記録する。
- 配布ZIPのサイズを把握し、記録する。

## スコープ外

- インストーラ（MSI / Inno Setup など）の作成。コピーで済む形を目標とする。
- コード署名。個人利用のため署名なしとする（SmartScreen の警告は許容し、その旨をドキュメントに記す）。
- Windows 以外のプラットフォーム向けビルド。
- 自動更新機構。
- GitHub Actions でのリリース自動化。
