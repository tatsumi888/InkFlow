# 要求内容

## 概要

B5〜A4サイズの雑誌記事PDF（記事ごとに分冊）を、Kindle Paperwhite で快適に読める**固定レイアウトEPUB**に再ページ化するデスクトップアプリ「InkFlow」を開発する。1つの原稿ページを「ページ全体（俯瞰）＋分割コマ」の複数ページに展開し、月刊誌1号分をまとめた1冊として出力する。

## 背景

雑誌PDFをそのままKindle Paperwhiteへ送ると、次のジレンマに陥る。

- **ページ全体表示**: B5〜A4の版面が6インチ級の画面に収まるため、本文の文字が小さすぎて読めない。
- **拡大表示**: 読めるサイズまで拡大すると1画面に収まらず、パン（スクロール）操作が必要になる。電子ペーパーは再描画が遅くタッチ追従も悪いため、パン主体の操作は実用に耐えない。

そこで**拡大とパンを、あらかじめ「ページ送り」に変換しておく**。原稿の版面を読み順に切り分け、各コマを端末の画面いっぱいに割り付けた固定レイアウトEPUBを事前生成すれば、読者は端末上でページ送りだけで読み進められる。

テキスト抽出によるリフローEPUB化は、多段組・図版・キャプションが混在する雑誌ではレイアウト崩壊のリスクが高い。一方、**ページを画像として扱えばレイアウトは確実に保持される**ため、本アプリは画像ベースを採用する。

同期は月1回・全体40ページ程度を想定するため、1号分を1ファイルにまとめ、記事ごとのしおり（目次）で移動できることを重視する。

## 実装対象の機能

### 1. PDFページの再ページ化（分割エンジン）

- 記事PDFの各ページを画像としてレンダリングし、選択したレイアウトに従って複数のコマへ切り分ける。
- 既定レイアウトは「二段組4分割」：**ページ全体 → 左上 → 左下 → 右上 → 右下** の計5ページに展開する。
- レイアウトはページ単位で選択できる（全体のみ／二段組4分割／一段組4分割／上下2分割／左右2分割／二段組6分割／三分割 など）。
- コマ間に微小なオーバーラップを持たせ、分割線上の行が読めなくなることを防ぐ。
- ページ周囲の白余白を自動トリムしてから分割することで、本文の実効表示サイズを最大化する。

### 2. Kindle最適化された画像生成

- 出力コマを端末解像度（既定: Paperwhite 1236×1648）ちょうどに正規化する。
- グレースケール化・コントラスト自動調整・ガンマ補正・アンシャープマスクを適用し、電子ペーパーでの視認性を高める。
- 16階調に量子化して、画質を保ったままファイルサイズを抑える。

### 3. 固定レイアウトEPUBの出力

- 全記事のコマを順に並べた、1画像＝1ページの固定レイアウトEPUBを生成する。
- Kindle が固定レイアウトとして解釈するメタデータ（`fixed-layout` / `original-resolution` / `book-type` など）を付与する。
- **記事ごとにしおり（目次項目）**を付け、記事の先頭ページへ移動できるようにする。
- 表紙は雑誌名＋号（例: 「〇〇マガジン 2026年8月号」）から自動生成する。任意の画像ファイルを表紙に指定することもできる。

### 4. GUI（分割レイアウトの選択・確認）

- 記事PDFを追加し、読む順に並べ替えられる。記事タイトルはしおり名として編集できる。
- ページのプレビュー上に分割枠と読み順の番号を重ねて表示し、出力結果を事前に確認できる。
- ページごとにレイアウトを選択できる。**「前ページと同じ」**、「この記事の全ページに適用」、「全ページに適用」の一括操作を備える。
- キーボードのみで送り作業ができる（←/→でページ移動、数字キーでレイアウト選択、Enterで前ページと同じを適用して次へ）。
- 作業内容をプロジェクトファイルに保存・再開できる。

### 5. CLIバッチ出力

- 保存済みプロジェクトファイル、またはPDFを並べたフォルダを指定して、GUIを起動せずEPUBを生成できる。

## 受け入れ条件

### PDFページの再ページ化（分割エンジン）

- [ ] 1ページのPDFに既定レイアウトを適用すると、出力ページが5枚になる。
- [ ] 二段組4分割の読み順が「全体 → 左上 → 左下 → 右上 → 右下」になっている。
- [ ] 一段組4分割の読み順が「全体 → 左上 → 右上 → 左下 → 右下」になっている。
- [ ] 「全体のみ」レイアウトを選ぶと、そのページの出力は1枚になる。
- [ ] 「全体ページを含める」をオフにすると、そのページの出力から俯瞰ページが除かれる。
- [ ] オーバーラップ設定を上げると、隣接コマの重複領域が広がる（矩形計算で検証可能）。
- [ ] 周囲に白余白があるPDFで自動トリムを有効にすると、トリム無効時より本文が大きく描画される。

### Kindle最適化された画像生成

- [ ] 出力画像がすべて端末解像度（既定1236×1648）ちょうどの寸法になっている。
- [ ] 出力画像がグレースケール（16階調以下）である。
- [ ] アスペクト比が異なるコマは、縦横比を保ったまま白でパディングされる（引き伸ばされない）。

### 固定レイアウトEPUBの出力

- [ ] 生成したEPUBが ZIP として展開でき、`mimetype` が先頭かつ無圧縮で格納されている。
- [ ] `content.opf` に `rendition:layout=pre-paginated` と Kindle 向けメタデータが含まれる。
- [ ] spine のページ数が「表紙1 ＋ 全記事の総コマ数」と一致する。
- [ ] `nav.xhtml` と `toc.ncx` の両方に、記事数ぶんのしおり項目が記事順に並ぶ。
- [ ] 各しおりのリンク先が、その記事の先頭ページのXHTMLになっている。
- [ ] 表紙画像が生成され、`content.opf` の cover メタデータから参照されている。

### GUI

- [ ] PDFを追加すると記事リストに並び、上下移動で順序を変更できる。
- [ ] プレビュー上に分割枠と読み順番号が表示される。
- [ ] レイアウトを変更すると、プレビューの枠と番号が即座に更新される。
- [ ] 「前ページと同じ」でひとつ前のページのレイアウト設定が複製される。
- [ ] 「この記事の全ページに適用」「全ページに適用」が期待どおり反映される。
- [ ] プロジェクトを保存して開き直すと、記事順・タイトル・ページごとのレイアウトが復元される。
- [ ] EPUB出力中にウィンドウが固まらず、進捗が表示される。

### CLIバッチ出力

- [ ] プロジェクトファイルを指定して実行するとEPUBが生成される。
- [ ] PDFを並べたフォルダを指定して実行すると、既定レイアウトでEPUBが生成される。

## 成功指標

- Paperwhite（1236×1648）で、B5誌面の本文が**パンなしで読めるサイズ**になる（既定の4分割時、本文文字高が画面高の 1/40 以上）。
- 40ページ相当（=出力200ページ相当）の1号分を、**EPUB 1ファイル 50MB以下**で出力できる。Send to Kindle のメール添付上限に収まる。
- 40ページ分のレイアウト確認・調整が、既定値のまま送るだけなら**操作ゼロ**、例外ページのみ手当てする運用で**5分以内**に完了する。

## スコープ外

以下はこのフェーズでは実装しません:

- テキスト抽出によるリフロー型EPUBの生成（レイアウト崩壊リスクのため採用しない）
- OCR、および本文・段組の自動検出（レイアウトは人手選択とする）
- 傾き補正・ノイズ除去などのスキャン画像向け前処理
- 縦組み（右→左）専用の読み順プリセット（横組み前提。将来拡張として設計のみ考慮）
- MOBI/AZW3 形式での出力、Kindle端末への自動転送・送信
- 見開き（2ページ連結）の扱い
