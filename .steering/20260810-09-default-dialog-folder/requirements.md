# 要求内容

## 概要

プロジェクト保存・EPUB出力・PDF追加のファイル選択ダイアログで、そのプロジェクトの記事PDFがあるフォルダを既定の開始位置にする。

## 背景

現状、プロジェクトを保存するダイアログもEPUB出力先を選ぶダイアログも、保存済みプロジェクトファイルが無い間は特にフォルダを指定していない（Qt/OSの既定に任せている）。記事PDFは通常、雑誌の号ごとにまとまったフォルダ（例: `D:\magazines\2026-08\articles\`）に置かれているため、保存・出力の行き先も同じ場所かその近くになることが多い。既定の開始位置がそこと無関係だと、毎回フォルダをたどり直す手間が生じる。

## 実装対象の機能

### 1. 既定フォルダの決定

- 対象: 「記事PDFを追加」「プロジェクトを保存（名前を付けて保存）」「EPUBの保存先」の3つのダイアログ。
- ユーザーがこのプロジェクトで**一度でも**上記いずれかのダイアログでフォルダを選んでいれば、以後はそこを優先する（毎回PDFフォルダへ強制的に戻さない。実際に選んだ場所を尊重する）。
- まだ一度も選んでいない場合、記事が1件以上あれば、直近に追加した記事PDFのフォルダを既定にする。ドラッグ＆ドロップで追加した記事も対象に含む（ダイアログを経由していなくても、記事の実際のパスから求めるため自然に対象になる）。
- 記事も無くユーザーの選択履歴も無い場合は、これまでどおり（Qt/OSの既定）。
- 「新規プロジェクト」「プロジェクトを開く」を行うと、選択履歴はリセットする（別のプロジェクトの文脈に切り替わるため）。

### 2. 対象外

- 「プロジェクトを開く」（既存の `.inkflow.json` を選ぶダイアログ）は対象外とする。これから読み込む別のプロジェクトを選ぶ操作であり、今開いている（まもなく破棄される）プロジェクトのPDFフォルダを基準にする理由が薄いため。
- 「本の設定」ダイアログの表紙画像選択は対象外とする。PDFフォルダとは性質の異なるファイルを選ぶ操作のため。

## 受け入れ条件

- [ ] 記事が0件の新規プロジェクトで「プロジェクトを保存」を開くと、既定の動作（フォルダ指定なし）のままである。
- [ ] 記事PDFを追加した後に「プロジェクトを保存」を開くと、直近に追加した記事PDFのフォルダが既定になる。
- [ ] 同様に、記事PDFを追加した後に「EPUBの保存先」を開くと、記事PDFのフォルダが既定になる。
- [ ] 記事PDFを追加した後に「記事PDFを追加」をもう一度開くと、既に追加済みの記事PDFのフォルダが既定になる。
- [ ] ドラッグ＆ドロップで記事PDFを追加した場合も、同様に既定フォルダとして反映される。
- [ ] いずれかのダイアログでユーザーが実際にフォルダを選ぶと、以後はそのフォルダが既定になる（記事PDFのフォルダより優先する）。
- [ ] 「新規プロジェクト」を実行すると、既定フォルダの記憶はリセットされる。
- [ ] 「プロジェクトを開く」で別プロジェクトを読み込むと、既定フォルダの記憶はリセットされ、読み込んだプロジェクトの記事PDFフォルダが（選択履歴が無い間は）既定になる。
- [ ] プロジェクトファイルが既に保存済みの場合、EPUB出力先の既定は従来どおりプロジェクトファイルの場所を優先する（この変更で既存の挙動を壊さない）。

## スコープ外

- 「プロジェクトを開く」ダイアログの既定フォルダ変更。
- 「本の設定」ダイアログの表紙画像選択の既定フォルダ変更。
- 既定フォルダの記憶をプロジェクトファイルへ永続化すること（アプリ実行中のみのメモリ上の状態とする）。
