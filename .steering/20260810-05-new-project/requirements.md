# 要求内容

## 概要

GUIに「新規プロジェクト」機能を追加する。現在は起動時の空プロジェクトから始めるか、既存プロジェクトを開くことしかできず、**作業中のプロジェクトを新しい号のために作り直す手段がない**（アプリを再起動するしかない）。

## 背景

InkFlowは月刊誌の号ごとに1プロジェクトを作る運用を想定している。前号のプロジェクトを開いたまま次号の作業を始めようとすると、現状では「記事を1件ずつ削除する」か「アプリを再起動する」しかない。前者は40ページ分の設定が残ったままになりかねず事故の元、後者は単純に手間である。

「プロジェクトを開く」には既に**未保存の変更を確認するガード**（`_confirm_discard_changes`）が備わっている。新規プロジェクトも同じ安全網の上に、白紙の状態へ戻す操作として自然に追加できる。

## 実装対象の機能

### 1. 新規プロジェクトの作成

- ［ファイル］メニューに「新規プロジェクト…」を追加する（`Ctrl+N`）。
- 未保存の変更があれば、既存の「プロジェクトを開く」と同じ確認ダイアログ（保存／破棄／キャンセル）を出す。キャンセルなら何もしない。
- 確認を通過したら、雑誌名・号・端末などを入力する画面（既存の「本の設定」ダイアログを流用）を出す。ここでキャンセルすれば、**現在のプロジェクトは変更しない**。
- 設定を確定したら、記事0件・既定のレイアウト設定を持つ真っ白なプロジェクトに切り替える。
- 新規プロジェクトは保存先（`project_path`）を持たない。最初の保存は「名前を付けて保存」になる。
- プレビューキャッシュを破棄し、ページ位置・記事一覧・要約表示など画面全体を新規プロジェクトの状態に更新する。
- 新規作成の直後は「未保存」扱いにしない（起動直後の空プロジェクトと同じ扱い）。

### 2. CLIとの関係

- CLI 側は既存の `inkflow.cli init` が「フォルダから新規プロジェクトファイルを作る」役割を既に担っている。今回はGUI側の欠落を埋めるのが目的であり、CLIへの変更は行わない。

## 受け入れ条件

- [ ] ［ファイル］メニューに「新規プロジェクト…」があり、`Ctrl+N` で呼び出せる。
- [ ] 未保存の変更がある状態で実行し、確認ダイアログで「キャンセル」を選ぶと、プロジェクトは変更されない。
- [ ] 確認ダイアログで「破棄」を選ぶと処理が進む。「保存」を選ぶと保存してから処理が進む。
- [ ] 本の設定ダイアログで「キャンセル」すると、現在のプロジェクトは一切変更されない（記事もタイトルもそのまま）。
- [ ] 本の設定ダイアログで入力した雑誌名・号が、新しいプロジェクトに反映される。
- [ ] 新規作成後、記事一覧が空になり、ページ送りの位置が先頭（0/0）に戻る。
- [ ] 新規作成後、`project_path` が `None` になり、保存すると「名前を付けて保存」ダイアログが出る。
- [ ] 新規作成直後は「未保存」マークが付かない。
- [ ] 空のプロジェクト（起動直後の状態）から実行しても落ちない。

## スコープ外

- CLIへの「新規プロジェクト」相当コマンドの追加（既存の `init` で足りている）。
- 新規作成時にPDFを同じダイアログで追加できるようにすること（既存の「PDFを追加」操作で別途行う）。
- 直近使ったプロジェクトの一覧（最近使ったファイル）機能。
