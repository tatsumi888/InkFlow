# プロジェクト用語集 (Glossary)

## 概要

InkFlowで使われる用語を定義する。日本語のドキュメント・コード内コメント・GUI表示文言はすべてこの用語集の表記に揃える。

**更新日**: 2026-08-10

## ドメイン用語

### 俯瞰（ふかん）／俯瞰ページ

**定義**: 原稿1ページの全体像を、分割前のまま1枚の出力ページとして収めたもの。

**説明**: 分割コマだけでは誌面の構成（どこに何が書かれているか）が分かりにくいため、既定では分割コマの前に俯瞰ページを1枚挟む。`PageSpec.include_overview` で有効/無効を切り替えられる。英語識別子・変数名としては `overview` を使う。

**関連用語**: 分割コマ、縦横入替、`full` レイアウト、しおり（俯瞰ページには原稿ページ番号をタイトルにした子しおりが付く）

**使用例**:
- 「ページ全体（俯瞰）も出力する」（GUIのチェックボックス文言）
- `PageSpec.include_overview: bool`

**英語表記**: Overview (page)

### 分割コマ

**定義**: 原稿1ページを分割レイアウトに従って切り出した、個々の出力ページ。

**説明**: 「コマ」は単体では「俯瞰以外の出力ページ1枚」を指す。読み順に並んだコマの列を`layouts.reading_rects()`が返す。コード内では `part`（`part_index`）と呼ぶ。

**関連用語**: 俯瞰、レイアウト、読み順

**英語表記**: Part / Crop

### 読み順

**定義**: 分割コマをどの順番でページ送りさせるか。

**説明**: `Layout.rects` タプルの並び順がそのまま読み順になる。既定レイアウト（`quad_2col`、二段組4分割）は「左上→左下→右上→右下」（2段組の左段を上から下へ読み切ってから右段へ移る）。段組のない誌面向けの `quad_1col`（一段組4分割）は「左上→右上→左下→右下」。

**関連用語**: レイアウト、分割コマ

**使用例**: プレビュー上の円形バッジの数字（1, 2, 3, 4…）が読み順を示す。

### 縦横入替（回転）

**定義**: 出力コマを90°回転させる設定。「右90°」（時計回り）と「左90°」（反時計回り）がある。

**説明**: 横長のコマ（上下2分割など）は画面にそのまま収めると上下が余って文字が小さくなるため、90°回して端末を横向きに持てば画面を使い切れる。縦長のコマでは逆に不利になるため自動判定はせず、ページ単位で人手選択する。**分割コマと俯瞰で別々に指定できる**（`PageSpec.rotate` / `PageSpec.rotate_overview`）。180°回転は扱わない（縦横入替という目的に意味がないため）。

**関連用語**: 分割コマ、俯瞰、`ROTATION_NONE` / `ROTATION_CW` / `ROTATION_CCW`

**使用例**: GUIの `R`（分割コマ）・`Shift+R`（俯瞰）キー、CLIの `--rotate` / `--rotate-overview`

**英語表記**: Rotation

### オーバーラップ

**定義**: 分割線上にかかった行が読めなくなるのを防ぐため、隣り合うコマ同士をわずかに重ねる処理。

**説明**: 矩形自身のサイズに対する比率（既定3%、片側あたり）で膨らませる。**行を断つ向きにだけ**効かせる（`Layout.overlap_axes`）。2段組の段間方向へ広げても隣の段の文字が混ざって画面が無駄になるだけのため。

**関連用語**: 分割コマ、`layouts.expand_rect()`

**英語表記**: Overlap

### 余白トリム

**定義**: 原稿ページ周囲の白い余白を自動検出して取り除き、本文の実効表示サイズを最大化する処理。

**説明**: 72dpiの下見レンダリング画像を輝度しきい値（既定245）で二値化し、`getbbox()` で本文領域を求める。検出結果が極端に小さい（ノンブル等の誤検出）場合はページ全面へフォールバックする。GUIのプレビューでは緑の破線枠で表示される。

**関連用語**: `imaging.find_content_bbox()`

**英語表記**: Auto-trim / Content bbox detection

### ノド／分割線の位置調整（既定位置固定・自動検出・手動）

**定義**: 2段組等の内部分割線（「ノド」＝段と段の間の余白）が、版面の非対称な余白のせいで既定位置（多くは50%）からズレて本文を切ってしまう問題への対処。

**説明**: `composer.resolve_divider_offsets()` が分割線の実際のオフセットを決める。`PageSpec.column_bias`（左右）/`row_bias`（上下）が数値（既定は `0.0`）ならその軸は既定位置に固定（またはその値をそのまま適用）し、自動検出は行わない。`None`（GUIで `[自動]` を明示的に押したときだけ入る値）のときだけ、既定位置の前後12%の範囲で最も広い余白帯を自動検出し、見つかればそこへ分割線を寄せる（見つからなければ既定位置のまま）。自動検出は既定で無効: 版面によっては過大な補正をしてしまうため、ページごとのオプトインにしてある。GUIでは右パネルの「分割位置の微調整」（`[－][自動][既定][＋]`）から、CLIでは `--column-bias`/`--row-bias`（数値指定、既定位置固定を一括設定）から操作する。

**関連用語**: 分割コマ、オーバーラップ、`imaging.find_divider_offset()`、`layouts.internal_dividers()`

**英語表記**: Gutter detection / Divider bias

### ショートカットプリセット

**定義**: 任意のページに適用した分割設定一式（`PageSpec` の `layout_id` / `include_overview` / `rotate` / `rotate_overview` / `column_bias` / `row_bias`）を5個のスロットへ保存し、キー1つで別のページへ呼び出せる機能。

**説明**: 右手をマウスに置いたまま左手だけで操作できるよう、QWERTY配列の左手側のみを使う。ホームロー `A S D F G`（適用）と、その真下 `Z X C V B`（保存）を同じ列で対応させる（`A`⇔`Z`など）。割り当ては号（プロジェクト）ごとではなくアプリ全体の設定として `%APPDATA%\InkFlow\config.json` に保存し、アプリを再起動しても引き継ぐ。右パネルに5スロットの内容を常時表示する。

**関連用語**: `PageSpec`、`inkflow/gui/shortcut_presets.py`

**英語表記**: Shortcut preset

### しおり

**定義**: EPUB内の目次項目。記事しおり（1記事につき1つ、その記事の先頭出力ページへ移動できる）と、俯瞰しおり（俯瞰ページ1枚につき1つ、直近の記事しおりの子項目として目次に現れる）の2種類がある。

**説明**: EPUB3の `nav.xhtml` と、互換のための `toc.ncx` の両方に同じ内容を書き出す（Send to Kindleの変換系によって参照先が異なるため）。記事しおりの名前は既定で記事タイトル（PDFファイル名）だが、GUIで編集できる。俯瞰しおりの名前は原稿ページ番号（例:「3ページ目」）で固定。目次は2階層になり、記事しおりをタップすると原稿ページ単位の俯瞰しおり一覧が展開される。

**関連用語**: 記事、俯瞰（ふかん）／俯瞰ページ、`epub_writer.py`、`epub_writer.pages_with_bookmarks()`

**英語表記**: Bookmark

### 記事

**定義**: 1本のPDFファイル。1冊（号）を構成する単位で、しおり1項目に対応する。

**関連用語**: しおり、号、`Article`

**英語表記**: Article

### 号（ごう）

**定義**: 雑誌の巻号。例:「2026年8月号」。`Project.issue` に対応し、`Project.title`（雑誌名）と合わせて本のタイトル（`book_title()`）を構成する。

**関連用語**: `Project`

**英語表記**: Issue

### プロジェクト

**定義**: 1号分の編集内容ひとそろい（雑誌名・号・端末設定・記事一覧・ページごとの分割/回転設定）。`*.inkflow.json` として保存される。

**関連用語**: `Project`、プロジェクトファイル

**英語表記**: Project

### 固定レイアウトEPUB

**定義**: EPUB3の `rendition:layout=pre-paginated` を使った、1画像＝1ページのEPUB。リフロー（文字の折り返しが端末幅に応じて変わる）ではなく、ページの見た目を完全に固定する。

**説明**: InkFlowはテキスト抽出によるリフロー変換を採用しない（多段組の雑誌ではレイアウトが崩壊するため）。画像として扱うことでレイアウトを100%保持する。

**関連用語**: `epub_writer.py`、Kindle固有メタデータ

**英語表記**: Fixed-layout EPUB

### 端末プリセット

**定義**: 出力解像度のあらかじめ用意された組み合わせ（例: `paperwhite_11` = 1236×1648）。

**説明**: `devices.py` の `DEVICES` に定義。`custom:WxH` 形式で任意解像度も指定できる。

**関連用語**: `Device`

**英語表記**: Device preset

### onedir / onefile

**定義**: PyInstallerの配布形式。onedirは実行ファイルとライブラリ一式を1フォルダにまとめる形式、onefileは単一の実行ファイルにまとめる形式。

**説明**: 実測でonedirは起動0.46秒、onefileは起動2.43秒（onefileは起動のたびに一時ディレクトリへ展開するため）。InkFlowの既定はonedir。

**関連用語**: `packaging/build.py`

### 自己診断（selftest）

**定義**: `inkflow.cli selftest` サブコマンド。PDF読み込み→画像処理→EPUB書き出し→Qt初期化までを実際に通し、この環境で正しく動くかを確認する。

**説明**: パッケージング後の実行ファイルに依存の取りこぼしがないかを検証する目的で作られた。`packaging/build.py` がビルド直後にこれを自動実行する。

**関連用語**: `packaging/build.py`、動作確認

**英語表記**: Self-test

## 技術用語

### PyMuPDF (pymupdf)

**定義**: PDFのラスタライズ（画像化）・ページ情報取得に使うPythonライブラリ。

**公式サイト**: https://pymupdf.readthedocs.io/

**本プロジェクトでの用途**: `renderer.py` でPDFページをグレースケール画像として直接ラスタライズする（RGB経由よりメモリを1/3に抑えるため）。

**バージョン**: `>=1.24`（`import pymupdf` を使う。`import fitz` は非推奨警告が出るため使わない）

### Pillow (PIL)

**定義**: 画像処理ライブラリ。

**本プロジェクトでの用途**: 余白トリム・クロップ・リサイズ・階調調整・量子化・表紙生成・アプリアイコン生成のすべてに使う（`imaging.py` `cover.py` `appicon.py`）。

**バージョン**: `>=10.0`

### PySide6 (Qt6)

**定義**: QtフレームワークのPython公式バインディング。

**本プロジェクトでの用途**: GUI全体（`inkflow/gui/`）。`QPainter` によるプレビューの分割枠オーバーレイ描画、`QThread` によるEPUB出力の非同期化に使う。

**バージョン**: `>=6.6`

**関連ドキュメント**: `docs/architecture.md` §6（並行処理）

### PyInstaller

**定義**: PythonスクリプトをWindows実行ファイル（`.exe`）へ固めるツール。

**本プロジェクトでの用途**: `packaging/inkflow.spec` の設定に従い、GUI用・CLI用の2実行ファイルを1つの `Analysis` から生成する。

**バージョン**: `>=6.0`（`requirements-dev.txt` のみに記載。実行時依存には含めない）

### zipfile（標準ライブラリ）

**定義**: Python標準のZIP読み書きライブラリ。

**本プロジェクトでの用途**: EPUB（実体はZIP）を直接組み立てる。`ebooklib` 等の外部ライブラリは導入せず、Kindle固有メタデータを完全に制御する。

## 略語・頭字語

### DPI

**正式名称**: Dots Per Inch

**意味**: 1インチあたりの画素数。PDFラスタライズの解像度を指定する単位。

**本プロジェクトでの使用**: `renderer.required_dpi()` が、出力コマが拡大も縮小もされず画面に収まる必要十分な値を算出する（72〜600でクランプ）。

### EPUB

**正式名称**: Electronic Publication

**意味**: 電子書籍の標準フォーマット（本プロジェクトはEPUB3を使用）。

**本プロジェクトでの使用**: 最終的な出力形式。`epub_writer.py` が生成する。

### GUI / CLI

**正式名称**: Graphical User Interface / Command Line Interface

**意味**: 画面操作のインターフェースと、コマンド操作のインターフェース。

**本プロジェクトでの使用**: `inkflow/gui/`（GUI）と `inkflow/cli.py`（CLI）。両者は `builder.build_epub()` を共通の入口として使い、出力が一致することをテストで担保している。

### ICO

**正式名称**: Icon（Windowsアイコンファイル形式）

**意味**: 複数解像度（16/32/48/256px等）を1ファイルに含められるWindows標準のアイコン形式。

**本プロジェクトでの使用**: `appicon.write_ico()` が生成し、実行ファイルへ埋め込む。

## アーキテクチャ用語

### 純粋ロジック

**定義**: 外部ライブラリ（Pillow・PyMuPDF・Qt）に依存しないモジュール。

**本プロジェクトでの適用**: `models.py` `layouts.py` `devices.py` の3つ。単体テストが軽量・高速になり、UI層からもインフラ層からも参照できる。

**関連コンポーネント**: `docs/architecture.md` §1

### CLI/GUI共通の唯一の入口

**定義**: EPUB生成において、GUIとCLIのどちらから呼んでも必ず通る単一の関数。

**本プロジェクトでの適用**: `builder.build_epub()`。ここを迂回する経路を新設しないことが開発規約として明記されている（`docs/development-guidelines.md`）。

**関連コンポーネント**: `builder.py`、`tests/test_cli.py::test_cli_and_gui_paths_produce_identical_pages`

### ワーカースレッド

**定義**: 時間のかかる処理をUIスレッドから切り離して実行する仕組み。

**本プロジェクトでの適用**: `gui/worker.py` の `BuildWorker`（`QThread` 継承）。EPUB出力中もGUIが固まらないようにする。`Project` のディープコピーを保持するため、生成中にUI側で設定を変えても出力に影響しない。

### ジェネレータ（再ページ化のストリーミング処理）

**定義**: `composer.compose()` が返すイテレータ。全出力ページを一度にメモリへ保持しない。

**本プロジェクトでの適用**: 200ページ規模の生成でも、出力画像（1枚約2MB）を同時に抱えない設計にしている。

## データモデル用語

### `Project`

**定義**: 1号分の編集内容ひとそろい。

**主要フィールド**:
- `title` / `issue`: 雑誌名・号
- `device_id`: 出力先端末プリセットID
- `defaults`: 新規ページの既定値（`PageDefaults`）
- `image`: 画像品質設定（`ImageOptions`）
- `articles`: 記事一覧（順序あり）
- `cover_image` / `project_path`: 表紙画像・保存先パス（いずれも省略可）

**関連エンティティ**: `Article`, `PageSpec`, `PageDefaults`, `ImageOptions`

**制約**: JSON化する際、PDFパスはプロジェクトファイルからの相対パスに変換される。

### `Article`

**定義**: 記事1本 = PDF 1ファイル = しおり1項目。

**主要フィールド**:
- `path`: PDFへのパス
- `title`: しおり名
- `pages`: 原稿ページごとの `PageSpec` の列

### `PageSpec`

**定義**: 原稿1ページぶんの分割・回転設定。

**主要フィールド**:
- `layout_id`: 分割レイアウトID
- `include_overview`: 俯瞰を出力するか
- `rotate`: 分割コマの縦横入替（0/90/270）
- `rotate_overview`: 俯瞰の縦横入替（`None` = 分割コマと同じ）
- `column_bias`/`row_bias`: 分割線のオフセット（±0.2。既定 `0.0`＝既定位置固定。`None` = 自動検出に任せる）

**制約**: `rotate_overview` が `None` の場合、`effective_overview_rotation()` が `rotate` の値を返す（「分割と同じ」の実体）。`column_bias`/`row_bias` は既定が `None` ではなく `0.0`（既定位置固定）である点が `rotate_overview` と異なる。`None` は GUIで `[自動]` を明示的に押したときだけ入る値で、そのときだけ自動検出結果が使われる。

### `Device`

**定義**: 端末プリセット1件（`id`, `label`, `width`, `height`）。`devices.py` で定義。

### `Layout`

**定義**: 分割レイアウト1件（`id`, `label`, `hint`, `rects`, `overlap_axes`）。`layouts.py` で定義。`rects` の並び順がそのまま読み順になる。

## エラー・例外

すべて `inkflow/errors.py` の `InkFlowError` を基底とする。

### `InkFlowError`

**クラス名**: `InkFlowError`

**発生条件**: InkFlow固有の全エラーの基底クラス。CLI/GUIはこの型だけを捕捉すればよい。

### `PdfLoadError`

**クラス名**: `PdfLoadError`

**発生条件**: PDFが開けない（存在しない・破損・パスワード保護されている）。

**対処方法**: パスワード保護PDFは復号を試みず、明示的にこのエラーで拒否する。

### `ProjectFormatError`

**クラス名**: `ProjectFormatError`

**発生条件**: プロジェクトJSONの構造が不正、または参照先PDFが見つからない。

### `RenderError`

**クラス名**: `RenderError`

**発生条件**: PDFページのラスタライズに失敗した。

**対処方法**: エラーメッセージに「どの記事の何ページ目か」を必ず含める（40ページの中から問題箇所を特定できるようにするため）。

### `EpubWriteError`

**クラス名**: `EpubWriteError`

**発生条件**: EPUBを書き出せない（出力先に書き込めない、ディスク不足など）。

**例**:
```python
raise EpubWriteError(f"EPUBを書き出せません: {output_path}（{e}）") from e
```

## 計算・アルゴリズム

### 必要DPIの算出

**定義**: 出力コマが拡大も縮小もされず画面いっぱいに収まる、必要十分なレンダリング解像度を求める計算。

**計算式**:
```
dpi = min(端末幅[px] / コマ幅[inch], 端末高[px] / コマ高[inch])
（72〜600dpiでクランプ）
```

**実装箇所**: `inkflow/renderer.py` の `required_dpi()`

**補足**: `max` ではなく `min` を採る。コマは縦横比を保って画面に収める（contain）ため、実際に効くのは縦横どちらか一方の制約だけであり、`min` を採ると収めたあとの倍率がちょうど1.0になり、拡大による滲みも縮小の再サンプリングも起きない。

**例**:
```
入力: 端末1236×1648px、コマ幅4.0in、コマ高8.0in
出力: min(1236/4.0, 1648/8.0) = min(309, 206) = 206dpi
```

### オーバーラップ矩形の計算

**定義**: 分割コマの矩形を、指定した比率だけ膨らませる計算。

**計算式**:
```
dx = (x1 - x0) * overlap   (axes に "x" を含むときのみ)
dy = (y1 - y0) * overlap   (axes に "y" を含むときのみ)
expanded = (max(0, x0-dx), max(0, y0-dy), min(1, x1+dx), min(1, y1+dy))
```

**実装箇所**: `inkflow/layouts.py` の `expand_rect()`

### 俯瞰と分割コマの解像度統合

**定義**: 俯瞰と分割コマで回転が異なる場合、両方の要求を満たす1つの解像度を求める計算。

**計算式**:
```
dpi = max(俯瞰側のrequired_dpi, 分割コマ側のrequired_dpi)
```

### 分割線の自動検出（ノド検出）

**定義**: 内部分割線の既定位置付近から、最も広い「ほぼ白い帯」を探し、あれば分割線をその中央へ寄せる計算。

**手順**:
```
1. Image.resize((width, 1) or (1, height), BOX) で列/行ごとの平均輝度プロファイルを得る
2. nominal ± 12%（既定）の範囲だけを見る
3. 輝度 ≥ 250（既定）が連続する最長区間を探す
4. 区間幅 < 1%（既定）なら「余白帯なし」として None（既定位置のまま）
5. 見つかった区間の中央と nominal の差分をオフセットとして返す
```

**実装箇所**: `inkflow/imaging.py` の `find_divider_offset()`、統合は `inkflow/composer.py` の `resolve_divider_offsets()`

**補足**: 探索窓を12%に絞るのは、レイアウト選択という既存の意図と無関係な余白（ページ上下の余白など）を誤って選ばないため。この計算自体は `PageSpec.column_bias`/`row_bias` が `None` のときだけ呼ばれる（既定値の `0.0` では呼ばれず既定位置固定）。

**実装箇所**: `inkflow/composer.py` の `_required_dpi_for_page()`

**補足**: 1ページにつきレンダリングは1回という原則を保つため、両方の要求のうち大きい方を採用する。俯瞰を出力しない設定のときは、俯瞰側の要求を計算に含めない。
