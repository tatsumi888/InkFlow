# 要求内容

## 概要

GitHub Actions で、`packaging/build.py` が作る配布物（onedir の配布用ZIP、onefile の実行ファイル2本）を自動生成する。バージョンタグを打てば GitHub Release に添付され、手動実行でも成果物を取得できるようにする。

## 背景

配布物は現状ローカルで `packaging/build.py` を手で実行して作るしかない。個人利用の道具とはいえ、別のPCへ配るときや、しばらく経ってから再ビルドするときに、毎回ローカル環境（Python・PyInstaller・依存関係）を用意し直すのは無駄が多い。CI上でビルドできれば、ソースだけあればいつでも同じ手順で作り直せる。

InkFlow はテスト・パッケージングの両方をこれまで一度もCIで検証していない。ビルドを自動化するこの機会に、**ビルド前提としてテストが通ることをCI上でも確認する**ゲートを含める。

## 実装対象の機能

### 1. ビルドワークフロー

- `v*` 形式のタグ（例: `v1.0.0`）を push したときに起動する。
- 手動実行（`workflow_dispatch`）でも起動できる。
- Windows ランナー上で実行する（PyInstaller は対象OS上でビルドする必要があるため）。
- ビルド前に `pytest -q` を実行し、失敗したらビルドへ進まない。
- onedir（配布用ZIP）と onefile（実行ファイル2本）の両方を作る。
- タグ起動のときは、タグのバージョン（例 `v1.0.0` の `1.0.0`）と `inkflow.__version__` が一致するか確認し、一致しなければ失敗させる（配布物のバージョン表記とタグのずれを防ぐ）。

### 2. 成果物の受け取り方

- 手動実行・タグ起動のどちらでも、Actions のワークフロー実行結果からアーティファクトとしてダウンロードできる。
- タグ起動のときは、さらに GitHub Release を作成（無ければ新規作成、あれば追記）し、配布用ZIPと onefile の実行ファイル2本を添付する。

## 受け入れ条件

- [ ] `v1.2.3` のようなタグを push すると、ワークフローが起動する。
- [ ] `workflow_dispatch` で手動実行できる。
- [ ] Windows ランナーで実行される。
- [ ] `pytest -q` が失敗すると、ビルドより先に失敗して終わる。
- [ ] タグと `inkflow.__version__` が一致しないと失敗する。
- [ ] 成功すると、onedir のZIPと onefile の2実行ファイルがアーティファクトとして取得できる。
- [ ] タグ起動のときは、そのタグ名の GitHub Release に上記の成果物が添付される。
- [ ] 手動実行のときはリリースを作らない（アーティファクトのみ）。

## スコープ外

- バージョン番号の自動採番・自動バンプ。
- Windows以外のプラットフォーム向けビルド。
- コード署名。
- push・PR ごとに毎回テストを走らせる汎用CI（`ci.yml`）。今回はビルドワークフロー自体にテストゲートを内蔵するに留める。
