# 開発ガイドライン

## 1. 検証コマンド

**このプロジェクトの検証は `pytest` のみ。** lint / 型チェックのスクリプトは設けていない。

```powershell
.venv\Scripts\python.exe -m pytest -q                          # 全テスト（必須）
.venv\Scripts\python.exe -m pytest tests/test_composer.py -q   # 単一ファイル
.venv\Scripts\python.exe -m pytest -k "overlap" -q             # 名前で絞る
.venv\Scripts\python.exe -m pytest -q --lf                     # 直前の失敗のみ
```

- `pytest.ini` が `pythonpath = .` を前提にしているので、**必ずリポジトリルートで実行する**。
- 仮想環境は**明示パス**で呼ぶ（`activate` に依存したコマンドを書かない）。
- 変更を完了と見なす条件は「全テストがグリーン」。

## 2. 環境

- Windows 11 / Python 3.12 / PowerShell 5.1（`&&` は使えない。`;` と `if ($?)` で繋ぐ）
- 仮想環境は `.venv\`。Anaconda は使わない（`venv` + `pip` のみ）
- **このディレクトリは Git リポジトリではない**。バージョン管理を前提とした操作をしない

## 3. コーディング規約

### 言語

- コメント・docstring・ユーザー向け文字列・ドキュメントは**すべて日本語**。
- 識別子は英語。

### 書き方

- `from __future__ import annotations` を先頭に置き、型注釈は組み込みジェネリクス（`list[str]` / `tuple[float, ...]` / `X | None`）で書く。
- データ構造は `dataclass`。変わらないものは `frozen=True`。
- 純粋モジュール（`layouts` / `models` / `devices`）に Pillow・PyMuPDF・Qt を持ち込まない。
- 1行は概ね100文字まで。
- モジュール冒頭の docstring には「何をするか」だけでなく**なぜその作りなのか**を書く。このプロジェクトは非自明な判断（処理順・オーバーラップの軸・レンダリング回数）が品質に直結するため。

### コメント

自明な処理にコメントを付けない。書くのは次の場合に限る。

- 順序に意味があるとき（「リサイズ後にシャープをかけるのは、縮小でぼけた輪郭を戻すため」）
- 一見冗長な処理の理由（「72dpi の下見を挟むのは、必要DPIをトリム後のサイズから決めるため」）
- 実測に基づく判断（「JPEG は文字主体の誌面では3倍以上に膨らむ」）

### エラー

- 下位モジュールは外部ライブラリ／OS の例外を `errors.py` の型へ `raise ... from e` で変換する。
- メッセージは日本語。**どのファイルのどのページか**を必ず含める。
- UI 層で捕まえるのは `InkFlowError` のみ。裸の `except Exception` はワーカースレッドの最終防衛線だけに許す。

## 4. テストの方針

### 原則

- 実物の雑誌PDFは持ち込まない。`tests/conftest.py` の `make_pdf()` が PyMuPDF で2段組ページを合成する。
- テスト名は日本語コメントではなく、英語の関数名で意図が読めるようにする（`test_two_column_layout_does_not_bleed_across_the_gutter`）。判断の根拠は docstring に日本語で書く。
- **振る舞いを検証する。** 実装の内部構造ではなく、出力ページ数・読み順・画像寸法・ZIP構造といった観測可能な結果を確かめる。

### 速度

重い統合テストは `custom:150x200` の小さな端末プロファイルを使う。実解像度（`paperwhite_11`）が必要なテストだけ実解像度を指定する。

### GUI

- `tests/conftest.py` が Qt の import 前に `QT_QPA_PLATFORM=offscreen` を設定するのでヘッドレスで走る。
- `QApplication` は session スコープのフィクスチャで1つだけ作る。
- ダイアログは `monkeypatch` で差し替える（`QMessageBox.question` / `QInputDialog.getText`）。
- ウィジェットは後始末する（`preview_cache.close()` / `deleteLater()`）。

### カバーすべき軸

新しい機能を足すときは、最低でも次を書く。

1. 正常系の代表ケース
2. 境界値（先頭・末尾・0件・1件）
3. 不正入力に対する例外の型とメッセージ
4. 設定を変えたときに結果が**期待どおりに変わる**こと（変わらないことも含む）

## 5. 変更時に守ること

### CLI と GUI の出力を分岐させない

両者は `builder.build_epub()` を共有している。ここを迂回する経路を新設しない。`tests/test_cli.py::test_cli_and_gui_paths_produce_identical_pages` が守っている。

### 新しいレイアウトには `overlap_axes` を設定する

省略すると既定の `("x", "y")` になり、2段組で段間方向に広がって隣の段の文字が混ざる。

### 画像パイプラインの順序を変えない

`imaging.finalize_page()` の
`リサイズ → コントラスト → ガンマ → シャープ → パディング → 量子化`
にはそれぞれ理由がある（`docs/architecture.md` §4）。順序を変えるなら、実際に出力画像を見て劣化しないことを確認する。回転は `finalize_page()` の**前**に掛ける（あとから回すと白パディング込みで回ってしまう）。

### `PageSpec` は `replace()` で組み立てる

GUI でレイアウトや俯瞰を変える処理は `dataclasses.replace(spec, ...)` を使う。`PageSpec(...)` と手で組み立てると、フィールドを増やしたときに既存の設定（`rotate` など）が黙って初期値に戻る。

### レンダリング回数を増やさない

`composer._compose_page()` は「下見1回＋本レンダリング1回」で、俯瞰も各コマもクロップで賄う。ここにレンダリングを足すと生成時間が倍以上になる。

### GUI に入力ウィジェットを置かない

数字キー（`1`〜`7`）をレイアウト選択のショートカットに割り当てているため、メインウィンドウに `QLineEdit` を置くと入力を奪われる。テキスト入力はモーダルダイアログ側に置く。

### パッケージングは実際に起動して確かめる

spec の除外リストを変えたら、必ず `packaging/build.py` の動作確認（`cli selftest`）を通す。依存の取りこぼしはテストでは検出できず、起動するまで分からない。`--no-verify` は調査中の一時的な用途に限る。

`inkflow/` から `packaging/` を参照しない。パッケージング方式を変えても本体に影響しない構造を保つ。

### サイズ削減の案内を書き換えるときは実測する

文字主体の誌面では JPEG が PNG の3倍以上に膨らむ、シャープをかけると**逆にサイズが減る**など、直感に反する結果が出ている。UI の案内文は実測値に基づいているので、変更するなら測り直す。

## 6. ステアリング

作業単位のドキュメントは `.steering/[YYYYMMDD]-[NN]-[機能名]/` に置く。

- `requirements.md` — 要求と受け入れ条件
- `design.md` — 設計
- `tasklist.md` — **進捗の正**

`tasklist.md` の `[ ]` → `[x]` は1タスクずつ即時更新する。全タスクが `[x]` になるまで作業は終わっていない。スキップは技術的理由がある場合のみ、理由を明記して記録する。完了後に振り返り（完了日・計画との差分・学び・改善案）を追記する。

永続ドキュメント（`docs/`）は、そのステアリングの結論として更新する。
